# Recall Card · React Frontend

기존 Recall Card의 N1 단어장 및 한자 데이터를 사용한 React + TypeScript + Vite 프론트엔드 프로토타입입니다.

## 기술 스택

- React
- TypeScript
- Vite
- lucide-react
- LocalStorage (백엔드 연결 전 임시 저장소)

## 실행

```bash
npm install
npm run dev
```

브라우저에서 Vite가 출력하는 주소를 엽니다. 기본 주소는 `http://localhost:5173`입니다.

## 빌드

```bash
npm run build
npm run preview
```

## 포함된 화면과 기능

- 홈 대시보드 및 학습 현황
- N1 DAY 01~20 라이브러리
- 카드 목록 검색
- 카드 추가
- 카드 앞/뒷면 학습
- 알고 있음 / 다시 보기 분류
- 수동 시작·일시정지가 가능한 학습 타이머
- 즐겨찾기
- 사용자 지정 카드 모음
- 한자 음훈독 검색 및 상세 예시
- 단어장별 진행률 통계
- 기존 HTML 호환 v7 JSON 전체 백업 및 복원
- 브라우저 음성 합성 발음 재생
- 학습 카드 옆 자유 필기장: 펜, 획 지우개, 한 획 취소, 모두 지우기, 모눈/줄/무지 배경, 확대/접기, 터치 및 펜 입력

## 데이터

`src/data/default-library.json`과 `src/data/kanji.json`은 기존에 제공된 Recall Card HTML에 포함된 기본 데이터를 추출한 파일입니다.

- 폴더 4개
- 단어장 20개
- 카드 2,026개
- 한자 46개
- 한자 예시 184개

카드 ID, 단어, 읽는 법, 뜻, 출처 페이지 등의 원본 기본 데이터는 그대로 유지했습니다.

## API 연결 준비

`src/services/apiClient.ts`에는 Spring Boot API 연결용 공통 fetch 클라이언트를 분리해 두었습니다. 현재 화면은 아직 이 API를 호출하지 않고 로컬 저장소를 사용합니다. 백엔드 개발 시 이 서비스 계층을 연결하면 됩니다. 개발 서버의 `/api` 요청은 `http://localhost:8080`으로 프록시되도록 설정했습니다.

`.env.example`의 `VITE_API_BASE_URL`로 API Prefix를 변경할 수 있습니다.

## 저장 방식 및 주의사항

현재 버전은 백엔드 연결 전 UI와 학습 흐름을 확인하기 위해 LocalStorage에 변경 사항을 저장합니다. 데이터는 현재 브라우저에만 저장되며 다른 기기와 동기화되지 않습니다.

브라우저 저장소를 비우거나 다른 브라우저에서 사용하기 전에 상단의 `백업` 기능으로 JSON을 내려받으세요.

기존 HTML의 LocalStorage 데이터와 자동으로 연결되지는 않습니다. **기존 HTML에서 JSON 전체 백업을 내려받은 뒤** React 화면 상단의 `복원`으로 가져오세요. 기존 `recall-cards-backup` v7 형식을 읽어 카드·폴더·학습 상태·즐겨찾기·모음을 새 저장 구조로 변환합니다. 단, 이것은 아직 무손실 양방향 마이그레이션이 아니므로 원본 JSON 파일을 따로 보존해야 합니다.

## 첨부한 원본 HTML과의 기능 비교 (복구 작업)

- 회독 진행 중 오답 카드 자동 섞기, 분류 차수, 원래 순서 정렬 및 회독 다시 시작
- 답 직접 입력 시험: 읽는 법 / 뜻 / 둘 다 및 기본 로마자 인정
- 학습 타이머 시작·일시정지, 완료 회독 시간과 오답 횟수 기록
- 카드 수정·삭제, 폴더 생성·이름 수정·빈 폴더 삭제, 단어장 생성·수정·삭제
- CSV 카드 가져오기·내보내기, 공부 기록 CSV, 한자 CSV
- 단어장별 즐겨찾기 학습, 사용자 모음별 독립 학습, 한자 셀프테스트
- 원본 v7 JSON 백업 가져오기(프로젝트에 맞는 필드를 데이터 구조로 변환)
- 원본 파일 자체는 `public/recall-card-original-reference.html`에 보존 (구현 동작 비교용)

현재 React 구현은 원본과 **완전히 동일한 수준이 아닙니다.** 원본 HTML을 기준으로 남은 차이(예: 일부 원본 UI 설정의 무손실 복원, 고급 음독·훈독 변형의 로마자 매칭, 원본과 동일한 전체 화면 흐름)는 추가 검증이 필요합니다.

복원 전에는 언제나 별도 백업을 보관하세요.
